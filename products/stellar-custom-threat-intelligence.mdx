## How the single feed is designed to work

The eventual external URL has the form **`https://<approved-host>/stellar-ti.tsv`**. No production hostname or customer-accessible endpoint has yet been approved or deployed; **do not register this placeholder URL** in Stellar Cyber.

| TSV column | Meaning |
| --- | --- |
| `TYPE` | `ip`, `domain` (future verified `url`, `md5-hash`, `sha1-hash`, `sha256-hash` where supported) |
| `VALUE` | Validated IOC itself |
| `SOURCE` | Original source, e.g. `OffSeqMirage` or `CERTPolska` |
| `SCORE` | Bounded 0–100 confidence/score |

The sample below contains **reserved example values only**, not live malicious IOCs:

```text
ip	203.0.113.9	OffSeqMirage	90
domain	phishing.example.invalid	CERTPolska	75
```

The internal collector preserves each source and type separately so source provenance, age, and risk can be validated. **Only the outward response is unified.** Before serving data, the gateway must independently check the publisher signature, signed source checksums, per-IOC evidence, Ed25519-approved release signature, freshness and anti-rollback sequence. Tampered, expired or unapproved releases fail closed rather than serving stale data.

**Freshness policy:** OffSeq records must have high-confidence high-impact behavior observed within 24 hours; CERT Polska domains must still be active and newly added within 24 hours. Evidence for removed or old records is not treated as a permanent blocklist. The design performs periodic collector QA but no unattended public distribution is enabled.

## Source rights, evidence, and limits

- [CERT Polska Warning List](https://cert.pl/en/warning-list/) — active phishing-domain information; commercial use allowed under its declared policy; no endorsement implied.
- [OffSeq Mirage original honeypot observations](https://github.com/offseq/mirage-feed) — source data are **CC BY 4.0**, requiring attribution; its signed original `SHA256SUMS` and Minisign proof are checked in QA.
- Jacobrakai honeypot — original-sensor correlation candidate only; its 14 credential-only records do **not** enter the customer-facing candidate.
- [Read the 41-source audit and exclusions](https://github.com/xdr-labs/xdr-labs-portal/blob/6a51bae8246f0154dd9f559a1036d7119a783740/docs/stellar-osint-strict-source-audit-20261122.md).

**What is verified:** unit/regression tests, signed original source checks, byte-for-byte source-to-IOC replay, one-URL synthetic HTTP QA, Suricata 7.0.3/8.0.1 checks. [CI evidence: 3/3 PASS](https://github.com/xdr-labs/xdr-labs-portal/actions/runs/44997698618).

**What is not verified or available:** public TLS origin, protected production signer, a continuously running customer feed, native Stellar Cyber 7.0 TIP polling/removal semantics, current OEM-indicator overlaps, a live Sensor→DP Alert/Case test, or operational detection/false-positive rates.
