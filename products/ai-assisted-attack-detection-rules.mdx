## Detection coverage

- **Common web attacks:** SQL injection, command injection, path traversal, XSS, webshell activity and executable uploads.
- **Selected AI-assisted and red-team tool indicators:** ARTEX, CyberStrikeAI, HexStrike-AI, Cobalt Strike, Havoc and others.
- **11 new v0.9 signatures:** /dev/tcp reverse shell indicators, encoded command separators, AntSword/China Chopper patterns, and Interactsh/Burp Collaborator OAST DNS lookups.

All signatures are alert-only and use any any → any any network/port headers. **They do not run an AI model.** Tool-specific fingerprints can be modified or spoofed.

## Real Stellar Cyber sensor PoC (November 8, 2026)

Beyond offline checks, we tested the deployed v0.9 pack on a **Stellar Cyber 7.0 Modular Sensor running Suricata 8.0.1**. A separate lab jump host sent inert HTTP/DNS requests through the network. We confirmed traffic capture on `eth0` and corresponding Suricata alerts in `eve.json`. No exploit or shell command was executed.

### The 11 new signatures confirmed on the sensor

| SID | Observed test pattern |
| --- | --- |
| `9006001` / `9006002` | `/dev/tcp` reverse-shell strings in HTTP URI / POST body |
| `9006009` | Encoded newline followed by an OS command (`%0a`) |
| `9006010` | AntSword User-Agent |
| `9006011` | PHP webshell manager pattern (`ini_set` plus `set_time_limit`) |
| `9006071` / `9006072` | Encoded command separators and shell substitution |
| `9006064`–`9006067` | Interactsh and Burp Collaborator OAST DNS lookups |

**Built-in IDS observations:** The pre-existing ET rule SID `2034825` also alerted on the lookalike domain `notburpcollaborator.net`. **This was not triggered by the newly added v0.9 signatures.** Two pre-existing ETPRO rules in `exploit.rules` (SIDs `2868495` and `2868498`) failed to load because `krb5` and `nfs` detection are disabled on the sensor. **No v0.9 custom-rule loading errors occurred.** Built-in rules and sensor configuration were left unchanged.

This verifies **real sensor-level IDS matching of 11 constructed, visible plaintext HTTP/DNS patterns**. It does not establish exploit execution, encrypted-traffic coverage, a production false-positive rate, or delivery of alerts to the Stellar Cyber DP/UI.

<Warning>
  **Verified on a real sensor in a controlled lab; not production-certified.** Back up existing custom_defined.rules before import because imports may overwrite the file. Check sensor compatibility and built-in IDS/ET overlap, and independently validate alert delivery to Stellar Cyber DP/UI.

**Known limits:** Added AD/DCERPC detections for DCSync, PetitPotam, PsExec and Kerberoasting were withheld until false positives can be distinguished from normal administration. A legacy v0.8 XSS rule can alert on benign HTML examples. Authorized penetration tests may also generate OAST DNS alerts. Encrypted HTTP content requires decryption or plaintext visibility.
