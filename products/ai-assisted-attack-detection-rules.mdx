## Import rules into Stellar Cyber 7.0

1. Back up existing custom rules. Importing a new file <strong>replaces</strong> the entire `custom_defined.rules` set on selected sensors rather than appending signatures.
2. Go to `System → Data Source Management → Sensors → Sensors`.
3. Select `Manage → Import Security Rules`.
4. Use `Choose File` to select the downloaded `.rules` file. Extract the ZIP first if needed.
5. Select target devices under `SENSORS` and click `Upload and Deploy`.
6. Check `Feature Customization → IDS → Signature → Selected Rules` in the assigned sensor profile for `custom_defined.rules`, and verify deployment feedback and alerts with authorized traffic.

<strong>Important:</strong> To preserve existing signatures, combine them with these 333 rules into a syntax-checked file with unique SIDs before importing. These `alert` rules do not block traffic.

## Why HOME_NET and EXTERNAL_NET matter

Many built-in Stellar Cyber IDS signatures use <strong>external-to-internal network direction</strong> in their rule headers, for example:

```suricata
alert tcp $EXTERNAL_NET any -> $HOME_NET any (msg:"Example inbound detection"; sid:1000001; rev:1;)
```

- `HOME_NET` identifies protected internal network ranges, e.g., `10.20.0.0/16` and `192.168.10.0/24`.
- `EXTERNAL_NET` identifies external or counterpart networks. Incorrect settings can cause built-in signatures using `$EXTERNAL_NET → $HOME_NET` to miss actual attacks because the traffic does not match the source/destination IP conditions.
- Some signatures instead use `$HOME_NET → $EXTERNAL_NET` for outbound traffic; their direction matters, too.

<strong>Configuration:</strong> Under `System → Data Source Management → Sensors → Sensor Profiles`, edit the assigned Modular Sensor Profile and set `Home Network` and `External Network` under `Feature Customization → IDS → Networks`. Choose `Specific` to enter actual IP ranges. Verify that `Network Traffic` and `IDS` are enabled and the profile is assigned to the desired sensors.

### Why this 333-rule bundle is different

<strong>All 333 signatures</strong> use `any any → any any` address headers, rather than referencing `$HOME_NET` or `$EXTERNAL_NET`:

```suricata
alert http any any -> any any (msg:"Example web attack pattern"; sid:1000002; rev:1;)
```

<strong>These 333 rules' address conditions do not depend on HOME_NET / EXTERNAL_NET values.</strong> They match attack patterns without restricting addresses to particular internal or external ranges. Protocol, `flow`, and content conditions still apply. The sensor must receive traffic and have IDS enabled; accurate HOME/EXTERNAL values remain important for built-in signatures and the sensor's IDS monitoring scope.
