# Stellar Data Exporter 사용 설명서

Stellar Data Exporter는 기능을 하나씩 배우는 것보다 **지금 하려는 작업과 비슷한 시나리오를 골라 그대로 따라하는 방식**이 가장 쉽습니다.

아래에서 목적에 맞는 시나리오를 선택하세요.

## 시작하기 전에

Exporter를 실행합니다.

```bash
git clone https://github.com/xdr-labs/stellar-data-exporter.git
cd stellar-data-exporter
uv sync --frozen
uv run stellar-data-exporter
```

Browser에서 다음 주소를 엽니다.

```text
http://127.0.0.1:8787
```

UI가 열리기 전에 Exporter HTTP Basic Login이 표시됩니다. 배포 관리자가 설정한 Exporter 계정으로 로그인하세요.

처음에는 **Basic** Mode로 시작하세요. 각 시나리오에서 필요한 경우에만 **Advanced** Mode로 전환합니다.

### 공통 연결 및 Tenant 선택

모든 시나리오에서 먼저 다음 절차를 수행합니다.

1. Stellar Cyber Host를 입력합니다.
2. Credential Type을 선택합니다.
   - **Root Scope** → Account Email + All-Access Token
   - **User Scope** → User API Key
3. **Test connection**을 실행합니다.
4. 해당 Credential로 접근 가능한 Tenant 목록이 표시됩니다.
5. Query 대상 **Tenant를 정확히 하나 선택**합니다. Preview, Count Check, Manual Export, Resume, Schedule은 모두 이 Tenant로 제한됩니다.
6. Host, Credential, Auth Mode, TLS 설정을 바꾸면 기존 Tenant 선택이 무효화되므로 **Test connection**을 다시 실행하고 Tenant를 재선택합니다.

### Run export를 누르면 실제로 일어나는 일

**Run export는 즉시 Export Job을 만들지 않습니다.** 먼저 선택한 Tenant, Data Source, Time Range, Query로 Count-Only Preflight를 실행합니다.

- `0건`이면 Export Job을 만들지 않습니다.
- 일반적인 크기라면 Count를 보여준 뒤 Export를 시작합니다.
- 결과가 크면 실제 Job 생성 전에 성능 저하 경고를 표시합니다.
- **Go back and refine**을 선택하면 안전하게 취소됩니다.
- 정말 필요하면 **Export anyway**를 선택해야 실제 Export가 시작됩니다.
- 기본 Warning 기준은 100,000건, Critical 기준은 1,000,000건이며 배포 환경에서 변경할 수 있습니다.

<Warning>
  **Record Limit**은 최종 Export Record 수를 제한하지만 Count Preflight는 원본 Query 전체를 확인합니다. 따라서 Multi-Source의 넓은 Query는 Record Limit이 작아도 Backend Search 자체가 무거울 수 있습니다.
</Warning>

## 시나리오 1 — 최근 1시간 Alert를 CSV로 받기

다음과 같은 요청을 받았을 때 사용합니다.

> “최근 1시간 Alert를 CSV 파일로 주세요.”

### 따라하기

1. 위의 **공통 연결 및 Tenant 선택**을 완료합니다.
2. Data Source에서 **Alerts**를 선택합니다.
3. Time Range에서 **1h** 버튼을 선택합니다.
4. Query에는 다음을 사용합니다.

```text
*:*
```

5. **Preview 100 records**를 실행합니다.
6. 원하는 Alert와 선택한 Tenant가 맞는지 확인합니다.
7. Output을 **CSV**로 선택합니다.
8. Destination을 **Download**로 선택합니다.
9. **Run export**를 실행합니다.
10. Count Preflight의 건수를 확인합니다. 대용량 경고가 나오면 Time/Query를 줄이거나 정말 필요한 경우에만 **Export anyway**를 선택합니다.

### 결과

선택한 최근 1시간 Alert가 CSV 파일로 Download됩니다.

<Tip>
  설치 후 첫 테스트는 이 시나리오가 가장 좋습니다. 먼저 짧은 시간 범위로 Preview를 확인한 뒤 더 큰 Export를 진행하세요.
</Tip>

## 시나리오 2 — User API Key로 원하는 Raw Data 찾기

**User Scope API Key**를 가지고 있고 Raw Data를 직접 검색하려는 경우입니다.

예:

> “최근 24시간 중 New 상태 Event만 찾아주세요.”

### 따라하기

1. **공통 연결 및 Tenant 선택**에서 **User Scope**를 선택하고 User API Key를 입력한 뒤 **Test connection**을 실행해 Tenant 하나를 선택합니다.
2. Data Source에서 예를 들어 **Alerts**를 선택합니다.
3. **24h** 버튼을 선택합니다.
4. **Stellar Cyber Query**에 다음을 입력합니다.

```text
event_status:New
```

5. **Preview 100 records**를 실행합니다.
6. Sample Record와 선택한 Tenant가 맞는지 확인합니다.
7. **JSON** 또는 **CSV**를 선택합니다.
8. Destination은 **Download**를 선택합니다.
9. **Run export**를 실행합니다.
10. 실제 Job이 시작되기 전에 표시되는 Count Preflight를 확인합니다.

### 결과

User API Key를 사용해 Raw Data를 검색하고 Query와 Time Range에 해당하는 결과만 Export합니다.

<Note>
  User Scope는 Account Email이 필요하지 않습니다. Stellar Cyber Query Mode가 자동으로 선택됩니다.
</Note>

## 시나리오 3 — 특정 네트워크의 Login Failure 조사하기

Incident Investigation 중 범위를 좁혀서 데이터를 받고 싶을 때 사용합니다.

예:

> “오늘 10.10.10.0/24에서 발생한 Login Failure만 보고 싶습니다.”

### 따라하기

1. **공통 연결 및 Tenant 선택**을 완료하고 조사할 Tenant를 선택합니다.
2. 조사할 Data Source를 선택합니다.
   - Windows Events
   - Linux Events
   - Alerts
3. 조사할 Start/End Time을 선택합니다.
4. Stellar Cyber Query에 예를 들어 다음을 입력합니다.

```text
event_name:"Login Failure" AND srcip:10.10.10.*
```

5. **Preview 100 records**를 실행합니다.
6. 다음 항목을 확인합니다.
   - Timestamp
   - Source IP
   - Event Name
   - 전체 Matching Count
7. Preview가 **0건**이면 예제 값이 현재 환경에 없는 것일 수 있습니다. 먼저 `*:*`로 Preview한 뒤 실제 데이터에 존재하는 `event_name`, `srcip` 값을 확인하고 그 값으로 조건을 다시 만드세요.
8. 결과가 너무 많으면 조건을 하나 더 추가합니다.
9. 원하는 데이터가 맞으면 **CSV**를 선택합니다.
10. **Run export**를 실행하고 Count Preflight를 확인합니다.

### 결과

전체 Raw Data를 먼저 내려받지 않고 실제 조사에 필요한 Record만 받을 수 있습니다.

## 시나리오 4 — 여러 Data Source를 한 번에 JSON으로 Export하기

같은 Incident 시간대의 여러 Source를 함께 수집할 때 사용합니다.

예:

> “같은 시간대의 Alerts, Traffic, Windows Events를 같이 모아주세요.”

### 따라하기

1. **공통 연결 및 Tenant 선택**을 완료하고 Incident 대상 Tenant를 선택합니다.
2. Data Source에서 다음을 같이 선택합니다.
   - **Alerts**
   - **Traffic**
   - **Windows Events**
3. 처음에는 짧은 Incident **Start** / **End** Time으로 시작합니다.
4. Incident에 필요한 조건으로 Query 범위를 충분히 좁힙니다.
5. **Preview 100 records**를 실행하고 **Matched records**를 확인합니다.
6. 예상보다 건수가 크면 Export하기 전에 Time Range를 더 줄이거나 Query 조건을 좁힙니다.
7. **Advanced**로 전환한 뒤 **Query Inspector**에서 **Resolved indices**와 Effective Query를 확인합니다.
8. Output은 **JSON**을 선택합니다.
9. 결과가 충분히 작을 때만 **Download**를 사용합니다. 결과가 크면 S3-Compatible Storage 또는 SFTP를 사용하세요.
10. **Run export**를 실행합니다. Exporter가 선택 Tenant의 전체 Query Count를 다시 확인합니다.
11. 대용량 경고가 표시되면 의도한 작업이 아니라면 **Go back and refine**으로 돌아가 Time/Query 범위를 줄입니다.

### 결과

선택한 여러 Source Family를 동일한 Time Range와 Query로 조회한 결과를 하나의 Export로 받을 수 있습니다.

<Warning>
  넓은 시간 범위에서 여러 Source에 `*:*`를 그대로 적용하지 마세요. 특히 Traffic 때문에 Matching Count가 매우 커질 수 있습니다. 데이터 양이 매우 크면 Stellar Cyber와 Exporter 양쪽에 부하가 증가하여 **시스템 성능 저하가 발생할 수 있습니다.** **Record Limit**은 최종 Export 건수만 제한하며 넓은 Backend Search 자체의 부하를 줄여준다고 보장할 수 없습니다. Preview의 Matching Count가 매우 크면 Time Range를 줄이거나 Query 조건을 추가한 뒤 Export하고, Browser Download보다 S3/SFTP를 우선 사용하세요.
</Warning>

<Tip>
  한 Source의 데이터가 너무 많다면 먼저 Source별로 Preview한 뒤 Multi-Source Export를 실행하세요.
</Tip>

## 시나리오 5 — 보고서에 필요한 Field만 CSV로 받기

Raw Record의 Field가 너무 많고 보고서에 필요한 값만 받고 싶을 때 사용합니다.

예:

> “timestamp, source IP, destination IP, event name, severity만 필요합니다.”

### 따라하기

1. **공통 연결 및 Tenant 선택**을 완료합니다.
2. Query를 작성하고 **Preview**를 먼저 실행합니다.
3. **Advanced**로 전환합니다.
4. Field Selector에서 필요한 Field만 선택합니다.
5. Output은 **CSV**를 선택합니다.
6. **Header**는 Enabled 상태로 둡니다.
7. **Run export**를 실행하고 Count Preflight를 확인합니다.

### 결과

Excel이나 다른 팀에 전달하기 쉬운 최소 Field CSV를 받을 수 있습니다.

## 시나리오 6 — 7일치 데이터를 S3 또는 Cloudflare R2로 보내기

Browser Download로 받기에는 데이터가 크거나 Object Storage로 바로 전달해야 할 때 사용합니다.

예:

> “7일치 Alerts를 R2 Bucket으로 Export하세요.”

### 따라하기

1. **공통 연결 및 Tenant 선택**을 완료합니다.
2. **Alerts**를 선택합니다.
3. **7d** 버튼을 선택하거나 정확한 Start/End Time을 지정합니다.
4. Query를 입력합니다.
5. 먼저 **Preview**를 실행합니다.
6. **Advanced**로 전환합니다.
7. 필요하면:
   - **gzip** Enable
   - **Max file size** 설정
   - 필요한 Field만 선택
8. Destination에서 **S3-compatible**을 선택합니다.
9. 다음 값을 입력합니다.
   - Endpoint URL
   - Region
   - Bucket
   - Prefix
   - Access Key
   - Secret Key
10. Destination Test를 실행합니다.
11. **Run export**를 실행합니다.
12. Count Preflight를 확인합니다. 대용량 경고는 실제 Job 생성 전에 표시되며, 정말 필요한 Export일 때만 **Export anyway**를 선택합니다.
13. Records / Bytes / Files / Progress를 확인합니다.

### 결과

대용량 결과를 Browser를 거치지 않고 AWS S3, Cloudflare R2, MinIO 등으로 직접 보냅니다.

<Tip>
  데이터가 매우 크다면 Max File Size를 지정해 여러 Part로 나누는 것이 좋습니다. Preview와 Run export 사이에도 새 Event가 유입될 수 있으므로 최종 Record Count는 Preview Count와 조금 달라질 수 있습니다.
</Tip>

## 시나리오 7 — 큰 Export를 여러 File로 나눠 SFTP 전송하기

외부 시스템이 SFTP로 파일을 받는 환경에서 사용합니다.

예:

> “최근 24시간 데이터를 500 MB씩 나눠 SFTP로 보내세요.”

### 따라하기

1. **공통 연결 및 Tenant 선택**을 완료합니다.
2. Query를 만들고 **Preview**로 먼저 검증합니다.
3. **Advanced**로 전환합니다.
4. Output Format을 선택합니다.
   - NDJSON
   - CSV
5. **Max file size**를 원하는 크기로 설정합니다.
6. 필요하면 **gzip**을 Enable합니다.
7. Destination을 **SFTP**로 선택합니다.
8. 다음 값을 입력합니다.
   - Host
   - Port
   - Username
   - Password 또는 Private Key
   - Remote Path
9. Destination Test를 실행합니다.
10. **Run export**를 실행하고 Count Preflight를 확인합니다.
11. 대용량 경고가 나오면 Tenant/Time/Query가 의도한 범위인지 확인한 뒤 필요한 경우에만 진행합니다.

### 결과

Remote Path에 번호가 붙은 여러 File이 생성됩니다. **Max file size**는 byte 단위의 절대 상한이라기보다 Split 목표값이므로, 하나의 Record가 경계를 넘는 경우 Part가 설정값보다 조금 커질 수 있습니다.

지원되는 Split Export가 중단되면 Job History에서 필요한 Credential을 다시 입력한 뒤 Retry/Resume할 수 있습니다.

## 시나리오 8 — 기존 Elasticsearch DSL을 그대로 사용하기

이미 사용 중인 Elasticsearch DSL Query가 있고 Root Scope Credential이 있을 때 사용합니다.

예:

> “이 DSL Query를 지정된 시간대에 실행해서 결과를 Export하세요.”

### 따라하기

1. **공통 연결 및 Tenant 선택**에서 **Root Scope**를 선택하고 Account Email + All-Access Token을 입력한 뒤 **Test connection**을 실행해 Tenant 하나를 선택합니다.
2. Data Source를 선택합니다.
3. Start/End Time을 설정합니다.
4. **Elasticsearch DSL**을 선택합니다.
5. Query를 붙여 넣습니다.

예:

```json
{
  "query": {
    "term": {
      "event_status": "New"
    }
  }
}
```

6. **Validate JSON**을 실행합니다.
7. **Preview 100 records**를 실행합니다.
8. 결과와 선택한 Tenant가 맞는지 확인합니다.
9. Output과 Destination을 선택합니다.
10. **Run export**를 실행하고 Count Preflight를 확인합니다.

### 결과

기존 DSL 조건에 UI에서 선택한 Time Range를 결합해서 Export합니다.

<Note>
  Elasticsearch DSL은 Account Email + All-Access Token을 사용하는 **Root Scope** 전용입니다. **User Scope API Key**에서는 DSL Mode가 의도적으로 Disabled되므로 시나리오 2의 Stellar Cyber Query를 사용하세요.
</Note>

## 시나리오 9 — 매시간 자동으로 S3/SFTP에 Export하기

같은 Export를 주기적으로 반복해야 할 때 사용합니다.

예:

> “매시간 새로운 Alert 데이터를 S3로 보내세요.”

### 따라하기

1. **공통 연결 및 Tenant 선택**을 완료하고 이 Schedule이 사용할 Tenant를 선택합니다.
2. 일반 S3/SFTP Export를 한 번 구성합니다.
3. Manual Export를 실행하고 Count Preflight를 확인한 뒤 실제로 성공하는지 검증합니다.
4. **Advanced**로 전환합니다.
5. Schedule을 생성합니다.
6. 다음을 설정합니다.
   - Schedule Name
   - Interval
   - Export Window
   - S3 또는 SFTP Destination
7. Schedule을 저장합니다.
8. **Run now**로 한 번 검증합니다.
9. 정상 동작하면 **Enabled** 상태로 둡니다.

선택한 Tenant는 암호화된 Schedule 설정에 함께 저장되며 Schedule의 Overlap/Resume Identity에도 포함됩니다.

### 결과

이전 성공 시점 이후의 연속된 Time Window를 기준으로 정기 Export가 실행됩니다.

<Warning>
  Scheduled Export는 Credential을 Encrypted At Rest로 저장합니다. 운영 환경에서는 `STELLAR_EXPORTER_SCHEDULE_KEY`에 고정된 Master Key를 설정하세요.
</Warning>

## 시나리오 10 — Preview나 Export 결과가 이상할 때 확인하기

Preview가 비어 있거나 Record Count가 예상과 다르거나 Export가 너무 클 때 사용합니다.

### 따라하기

1. **Test connection**이 성공했고 의도한 Tenant가 선택되어 있는지 확인합니다. Host/API Credential을 바꿨다면 Tenant 목록을 다시 불러와 재선택합니다.
2. **Advanced**로 전환합니다. **Query Inspector**는 Query 영역 안에 자동으로 표시되며 별도의 Open 버튼은 없습니다.
3. 일반 Query 설정에서 선택한 Data Source와 Start/End Time을 확인합니다.
4. **Query Inspector**에서 다음을 확인합니다.
   - Request Path와 **Resolved indices**
   - 선택 Tenant/Time Filter가 포함된 Effective Query
   - **Matched records**, Preview Latency/Bytes, Estimated Output Size
   - **Export Plan**의 Selected Fields, Export Limit, Adaptive Slicing, Estimated Slices/Files, Max File Size, Overlap Policy
5. Matched Count 또는 Estimated Output Size가 너무 크면 Time Range를 줄입니다.
6. Preview를 다시 실행합니다.
7. Query 조건을 하나씩 추가합니다.
8. Preview 결과가 맞을 때만 **Run export**를 누르고, 새로 계산된 Count Preflight를 확인한 뒤 진행합니다.

### 자주 해결되는 방법

| 문제 | 먼저 해볼 것 |
| --- | --- |
| Exporter Login이 반복됨 | 배포 관리자가 설정한 Exporter HTTP Basic Login을 다시 확인 |
| Stellar Authentication failed | Root/User Scope 선택과 입력한 Stellar Cyber Credential Type이 맞는지 확인 |
| Tenant Selector가 Disabled | **Test connection**을 다시 실행. Host/API Credential 변경 시 기존 Tenant 선택은 무효화됨 |
| Preview가 0건 | Tenant를 먼저 확인한 뒤 Time Range를 넓히거나 Query를 단순화 |
| 결과가 너무 많음 | Run export 전에 Time Range를 줄이거나 Query Condition 추가 |
| 대용량 경고가 표시됨 | 새 Count를 확인하고 의도한 대용량 작업이 아니면 **Go back and refine** 선택 |
| Elasticsearch DSL이 Disabled | User Scope이므로 Stellar Cyber Query 사용 |
| Browser Export가 너무 큼 | S3/SFTP, gzip, Field 선택, File Split 사용 |
| S3/SFTP 실패 | Destination Test 후 Credential/Path 설정 재확인 |
