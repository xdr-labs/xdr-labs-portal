> **검증 범위 안내:** 기존 v1.0 333개 중 **331개는 실제 센서 트래픽으로 개별 Alert가 확인**되었습니다. 새로 추가한 Java4Shell 룰 6개는 **Stellar Cyber 7.0 Modular Sensor에서 오프라인 PCAP 재생**으로 탐지를 확인했으며, **10/10** 테스트 케이스가 기대 결과와 일치했습니다. 이를 전체 339개의 운영 트래픽·Data Processor UI Alert 검증 완료로 해석해서는 안 됩니다.

## v1.1 업데이트 내용 (2026년 11월 18일)

기존 333개 룰의 원본과 SID는 그대로 보존하고, CVE-2026-114938 관련 네트워크 탐지 룰 6개를 추가했습니다. 공개 커뮤니티 탐지 패턴을 Suricata 8.0.1에 맞게 보정했고, 정상적인 Base64 패딩에서도 발생하던 오탐을 재현·수정했습니다.

| 추가 SID | 탐지 대상 |
| --- | --- |
| `9006101` | HTTP Basic 인증의 비정상 길이 Base64 패딩 |
| `9006102` | 패딩 오류를 포함한 64자 Base64 테스트 패턴 |
| `9006103` | 패딩 오류를 포함한 128자 Base64 테스트 패턴 |
| `9006104` | 60초 동안 단일 소스에서 발생한 Basic 인증 요청 1,000회 |
| `9006105` | HTTP 응답 본문에 노출된 JVM 충돌 문자열 |
| `9006106` | JWT Bearer 헤더의 비정상 Base64URL 패딩 |

이 룰은 **의심스러운 네트워크 지표**를 확인하는 용도이며, 특정 Java 서버의 취약 여부나 원격 코드 실행 성공을 확정하지 않습니다. 특히 `9006104`·`9006105`는 환경에 따라 정상 요청도 탐지할 수 있어 운영 전 튜닝이 필요합니다. HTTP 페이로드는 평문이거나 복호화된 트래픽에서만 검사할 수 있습니다.

[새로 추가한 6개 룰 상세 보기](https://github.com/xdr-labs/xdr-labs-portal/blob/main/downloads/java4shell-cve-2026-114938-6.rules).

## Stellar Cyber 7.0 룰 임포트

1. **현재 `custom_defined.rules`를 백업하세요.** 룰 임포트는 파일을 **전체 교체**하므로 신규 6개만 담긴 파일을 단독으로 임포트하면 안 됩니다.
2. 위에서 **v1.1 통합 339개 `.rules` 파일**을 다운로드하고 무결성을 확인합니다. SHA-256: `2478ffd6b3dbdfbb527695f07e00e1a106a554d8bb898a0f9584bb3845b07483`.
3. `System → Data Source Management → Sensors → Sensors → Manage → Import Security Rules`로 이동합니다.
4. 전체 `.rules` 파일을 선택하고 대상 센서를 지정한 뒤 `Upload and Deploy`를 실행합니다.
5. `Sensor Profiles → IDS → Signature → Selected Rules`에서 활성화를 확인하고, 탐지·오탐 및 실제 트래픽 가시성을 검증합니다.

### HOME_NET / EXTERNAL_NET 및 트래픽 가시성

이번 **339개 커스텀 룰**은 모두 `any any → any any` 주소 조건을 사용하므로 룰의 IP 매칭 범위가 `HOME_NET`·`EXTERNAL_NET` 설정에 직접 의존하지 않습니다. 다만 센서의 패킷 수집·IDS 활성화, 개별 룰의 프로토콜·`flow` 조건, HTTPS 복호화 제약은 적용됩니다. 다른 기본 ET/IDS 룰에는 `HOME_NET` 설정이 중요할 수 있으므로, 보호 대상 공인 IP를 포함한 실제 네트워크 범위를 센서 프로필에서 확인하세요.

**설정 위치:** `System → Data Source Management → Sensors → Sensor Profiles → Feature Customization → IDS → Networks`.
